6) Expected technical questions & model answers

Open component:ApplicationLeave Requests

ITOM

Open component:DiscoveryMID ServersAlertsApplication Services

Q: Explain MID Server role.
A: On-prem bridge between instance and customer network for Discovery, JDBC, orchestration. Messages via ecc_queue. Required when targets are not reachable from cloud instance.

Q: Discovery vs Service Mapping?
A: Discovery = bottom-up, finds CIs via schedules/credentials. Service Mapping = top-down, maps application services from entry points. Both feed CMDB via IRE.

Q: em_event vs em_alert?
A: Event = raw signal from monitoring. Alert = correlated/actionable item; can drive incident creation.

Deep read: ../modules/ITOM.md, ../modules/CMDB.md

ITAM (prepare even if JD stresses it)

Open component:AssetsHardwareStockroomsPurchase Orders

Q: HAM vs SAM?
A: HAM = Hardware Asset Management (physical assets, lifecycle). SAM = Software Asset Management (licenses, compliance, reclamation).

Q: Key tables?
A: alm_asset, alm_hardware, alm_license, stockroom integration with procurement — align to client process.

Q: ITAM vs CMDB?
A: CMDB = configuration/relationships for service impact. ITAM = financial/lifecycle/contract view. Often integrated — asset record may link to CI.

SPM

Open component:DemandsProjectsPortfoliosResource Plans

Q: Idea → Demand → Project flow?
A: Intake governance via Demand Workbench; approved demand becomes project; WBS in Planning Console; resources in Resource Workbench; financials via cost/benefit plans.

Q: Portfolio vs Program vs Project?
A: Portfolio = strategic bucket; Program = related projects; Project = deliverable with tasks/stories.

Deep read: ../modules/SPM.md

IRM (GRC)

Open component:RisksControlsIssuesAudit Engagements

Q: GRC engine in one sentence?
A: Authority Document → Citation → Policy → Control → Indicator/Attestation → Issue if fail; Profiles scope entities.

Q: Inherent vs residual risk?
A: Inherent before controls; residual after treatment/monitoring.

Deep read: ../modules/GRC.md

Mobile

Open component:ApplicationLeave Requests

Q: Now Mobile vs Mobile Agent vs Service Portal mobile?
A: Now Mobile = platform for mobile experiences. Mobile Agent = field technician offline-capable UI. SP = employee self-service widgets (Angular).

Q: How do you test mobile?
A: Role-based test users, offline scenarios, sync conflicts, ACL via GlideRecordSecure on server scripts.

Consulting / Senior behavior

Open component:ApplicationLeave Requests

Q: How do you start a new ITOM implementation?
A: Workshop → current state → CSDM alignment → MID/credentials → pilot discovery → IRE rules → CMDB Health KPIs → expand schedules → handover/runbooks.

Q: Client wants everything at once — what do you do?
A: Phased roadmap: foundation (CMDB/IRE) → ITOM discover → operationalize events → SPM/IRM as phase 2. OOTB-first, scoped customizations.

Q: Tell me about a difficult issue you solved.
A: Use STAR: Situation, Task, Action, Result — real project (discovery duplicates, IRE, SLA, integration).
