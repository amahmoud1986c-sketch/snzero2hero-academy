1What the SDK is, and when to use it instead of Studio

Developer

The ServiceNow SDK is a Node command-line tool that lets you define platform artefacts as TypeScript source on your own machine, compile them into an installable application package, and install that package onto an instance. The TypeScript dialect you write is called Fluent: a set of typed factory functions — Table(), BusinessRule(), Acl(), Role(), Flow() — exported from @servicenow/sdk/core.

The thing most people miss on first contact: this is not a wrapper that drives the Studio UI, and it is not an update-set generator. It produces the application package itself. Your source files are the definition of the app; the instance is a deployment target.

1.1 The honest comparison

ConcernStudioSDK + Fluent
Where truth livesThe instanceYour git repository
Code reviewCompare update set XML, painfullyA normal pull request diff
RollbackBack out an update set and hopegit revert, rebuild, reinstall
Two developers on one appUpdate-set collisionsGit branches and merges
Record identity across instancessys_id travels in the update setPinned in committed keys.ts — see §5.3
Working offlineImpossibleEverything but install and query
AI coding assistanceWeak — the model cannot see a browser formStrong — it is just TypeScript in your editor
Learning curveLowReal. Expect a slow first week.
CoverageEverything on the platformWide but not total — check now-sdk explain --list before promising a feature
Who is comfortableAdmins, configuratorsDevelopers who already use git daily

Do not mix uncontrolled. If a table is defined in Fluent and someone also edits it in the instance UI, the next install can overwrite their change — and install --reinstall will definitely destroy any on-instance metadata that is not in your source. Decide per application: either it is SDK-managed, or it is Studio-managed. "Both" is how teams lose work.

1.2 When each one is the right answer

Use the SDK when…

More than one developer touches the app; you want pull-request review; you need repeatable deploys to several instances; you want an AI assistant to help write platform code.

Stay in Studio when…

You are configuring rather than building, the change is a one-off, the team has no git practice, or the artefact type has no Fluent API yet.

Hybrid that works

Core logic (tables, script includes, business rules, ACLs) in the SDK. Instance-specific configuration (properties values, scheduled job times, data) set on the instance.

Hybrid that fails

Editing Fluent-managed business rules in Studio "just this once". The next build silently reverts it and nobody can explain why.

mkdir my-app

2.3 Authentication — the complete auth surface

Credentials are stored in your OS keychain under an alias, never in the project. One alias per instance.

now-sdk authConfigure authentication to instance4.12.2
--add <instance>Instance name or URL to store credentials for. Prompts interactively unless you pipe a password.
--type <basic|oauth>Authentication type for the new credential. Only these two values.
--alias <name>The alias to store it under. Pick something short: dev, test.
--delete <alias>Delete a stored credential.
--listList all stored credentials.
--use <alias>Set an alias as the default for subsequent commands.
--print [alias]Print a live auth token for manual API calls. Omit the alias to use the default.
--format <headers|bearer|env>Output shape for --print. Default headers.
--password-stdinRead the password from stdin — the only safe way to script --add.
 
# interactive, the normal case
npx @servicenow/sdk auth --add https://dev398980.service-now.com --type basic --alias DEV

# list what you have
npx @servicenow/sdk auth --list

# make one the default so you can drop --auth from later commands
npx @servicenow/sdk auth --use DEV

# fully non-interactive (CI, containers) — password never appears in the command line
echo "$env:SN_PASSWORD" | npx @servicenow/sdk auth --add https://dev398980.service-now.com `
  --type basic --alias DEV --username admin --password-stdin

# remove it
npx @servicenow/sdk auth --delete DEV

2.4 auth --print — the flag worth knowing about

This is the most useful command almost nobody discovers. It mints a live token from a stored credential so you can hit the REST API by hand without ever typing a password into a terminal:

# ready-to-paste curl headers
npx @servicenow/sdk auth --print DEV --format headers

# just the bearer token, for scripting
npx @servicenow/sdk auth --print DEV --format bearer

# shell-exportable form
npx @servicenow/sdk auth --print DEV --format env

Combine it with now-sdk query (§3.11) and you have a complete read-only investigation toolkit for an instance without leaving your terminal.

Validation for §2: auth --list shows your alias, and auth --print <alias> --format bearer returns a token string. If the second one fails, the stored credential is wrong — delete and re-add it.

Captured from now-sdk <command> --help on SDK 4.12.2

Three global options apply to every command: -d, --debug (print debug output, default false), -h, --help, and -v, --version. Where a command takes a source or --directory argument, the default is the current working directory — so run commands from the project root and you can omit it.

3.2 init — create or convert a project

now-sdk initalias: create

Initialises a new ServiceNow custom application, applies a template to an existing application, or converts a legacy scoped application — from an instance or from a local directory — into a Fluent app.

--from <sys_id|path>sys_id of a legacy application on the instance, or a filesystem path to a directory containing a legacy scoped app, to convert into Fluent.
--appName <name>Display name of the application.
--packageName <name>npm package name for the project. Must follow npm naming rules.
--scopeName <scope>Scope name. Must start with your vendor prefix if you have one, and cannot exceed 18 characters.
-a, --auth <alias>Credential alias to authenticate with.
--template <id>Project template. Choices: partial.javascript.react, partial.javascript.basic, partial.typescript.react, partial.typescript.vue, partial.typescript.basic, partial.typescript.react-devserver.
 
# brand new app, fully specified so it never prompts
npx @servicenow/sdk init --appName "HR Leave" --packageName hr-leave-sdk `
  --scopeName x_786686_hr_leave --auth DEV

# with a UI template
npx @servicenow/sdk init --appName "Ops Console" --packageName ops-console `
  --scopeName x_acme_ops --template partial.typescript.react --auth DEV

# convert an existing scoped app that lives on the instance
npx @servicenow/sdk init --from c84db0e8839f0b509f02b0d6feaad3c9 --auth DEV

The 18-character scope limit is a hard stop. x_786686_hr_leave is 17. Plan the name before you create the app, because changing scope later means recreating it.

3.3 build — compile Fluent into an installable package

now-sdk build [source]the command you run most

Compiles everything in your fluentDir into app files and generates the installable package. It also regenerates src/fluent/generated/keys.ts — see §5.3, because that side effect matters more than anything else on this page.

sourcePositional. Path to the directory containing package.json. Defaults to the current directory.
--frozenKeysFail the build if keys.ts changed during it. Use this in CI. Default false. See §9.
--errorOnConflictTreat sys_id conflicts between Fluent and XML as errors rather than warnings. Fluent-to-Fluent conflicts are always errors regardless. Default false.
--skipCleanDo not clean output directories before building. Faster, occasionally stale. Default false.
--legacyChoicesGenerate choice set XML with the sys_choice_set wrapper — the destructive v3 behaviour — instead of sys_choice_v2 additive merge. Only for backward compatibility.
 
npx @servicenow/sdk build
npx @servicenow/sdk build --frozenKeys        # CI gate
npx @servicenow/sdk build --errorOnConflict   # strict mode, recommended once stable

There is no --watch flag. For a fast loop, use your own watcher, e.g. npx nodemon --watch src/fluent -e ts --exec "npx @servicenow/sdk build".

3.4 install — push the app to an instance

now-sdk installalias: deploy

Installs or updates the built application on an instance. deploy is an alias, so both spellings work; the canonical name is install.

--source <path>Project directory. Defaults to the current directory.
-a, --auth <alias>Credential alias. Omit to use the default set by auth --use.
-r, --reinstallUninstall and reinstall so instance metadata exactly matches the package. DESTRUCTIVE — metadata created on the instance that is not in your source is lost. Default false.
-b, --open-browserOpen the sys_app page in your default browser on success. Default false.
-i, --infoGet information from the instance about the most recent install of this app. Default false.
--asyncInstall asynchronously, falling back to synchronous if the instance does not support it. Default true.
--demoDataInstall demo data. Default true. Pass --demoData false to skip it.
--skip-flow-activationDo not activate (publish) flows after install. Default false — so flows are activated by default.
 
npx @servicenow/sdk install --auth DEV
npx @servicenow/sdk install --auth DEV --open-browser
npx @servicenow/sdk install --auth DEV --info          # what is currently installed?
npx @servicenow/sdk install --auth DEV --reinstall     # nuclear: read the warning first

Two defaults to notice. --demoData defaults to true, so demo data goes in unless you say otherwise. And flows are activated on install unless you pass --skip-flow-activation — which explains why the HR Leave approval flow in this project is marked "activated by install".

3.5 download — pull application metadata from an instance

now-sdk download <directory>
directoryRequired positional. Path to expand the application into.

3.6 transform — turn instance records into Fluent source

now-sdk transformthe adoption command

Downloads XML records from an instance, or reads them from a local path, and converts them into Fluent source code. This is how you migrate an existing application into the SDK one artefact type at a time instead of rewriting it.

--table <names>Comma-separated table names to transform by table hierarchy. Combined with --id it transforms one specific record and its relationships.
--forceAllow transforming descendant tables without their parent hierarchy. Default false.
--from <path>Path to a local XML file or directory to transform — no instance needed.
--directory <path>Project directory. Defaults to the current directory.
-a, --auth <alias>Credential alias.
-f, --formatAutomatically format new and updated source after transforming. Default true.
 
# bring every business rule and ACL of the app into Fluent
npx @servicenow/sdk transform --table sys_script,sys_security_acl --auth DEV

# convert an update set XML you already exported
npx @servicenow/sdk transform --from ./exports/update-set.xml

3.7 dependencies — types and declared dependencies

now-sdk dependencies [sysIds..]

Downloads the dependencies declared in now.config.json plus the TypeScript type definitions that make your editor autocomplete ServiceNow APIs. Run it after cloning the repo on a new machine.

sysIds..Positional array of sys_ids to add when using --add. Default empty.
--directory <path>Project directory.
-a, --auth <alias>Credential alias.
--type-defs-onlyDownload only the script type definitions (glide.*.d.ts).
--fluent-onlyDownload only Fluent types for the dependencies in now.config.json.
--add <table>Add a new dependency item by table name, e.g. actions, triggers, sys_security_acl.
--scope <scope>Scope for the dependency, e.g. global or x_my_app. Required with --add.
 
# after git clone

npx @servicenow/sdk dependencies --type-defs-only --auth DEV

npx @servicenow/sdk dependencies --add actions --scope global --auth DEV

This is the command that fixes "my editor has no autocomplete for GlideRecord". It is also the one most often forgotten after a fresh clone.

3.8 clean and pack

now-sdk clean [source]  ·  now-sdk pack [source]

clean removes the build output directory. Its only options are the global three plus the positional source.

pack zips the already-built app into an installable artefact — the .zip you can hand to someone or upload. One extra flag:

--skip-package-inventorySkip generating package_inventory.csv in the output. Default false.
 
npx @servicenow/sdk clean
npx @servicenow/sdk build
npx @servicenow/sdk pack
# → target/hr_leave_sdk_1_0_0.zip  (this project's artefact is 114 KB)

The package_inventory.csv that pack produces is a plain list of everything in the package. It is the fastest way to answer "did this build actually include the new ACL?" without unzipping anything.

3.9 query — read instance data from your terminal

now-sdk query <table>underrated

A full Table API client built into the CLI. Every sysparm_* you know from the REST API has a flag here, and it paginates for you.

tableRequired positional. Table name, e.g. incident, sys_user.
-q, --query <encoded>Required. Encoded query, e.g. "active=true^priority<=2".
--limit <n>Maximum records per page. Default 100.
--offset <n>Starting offset. Default 0.
-f, --fields <list>Comma-separated fields to return.
--display-value <v>true, false, or all for both raw and display. Default false.
--exclude-reference-linkStrip reference link metadata. Default true.
--no-countSkip total count calculation for speed. Default false.
--timeout <ms>Per-request timeout; each page fetch is bounded by it. Default 30000.
--view <name>UI view that determines which fields come back.
--query-category <c>Query category for extended queries.
--query-no-domainIgnore domain separation. Default false.
-a, --auth <alias>Credential alias.
-o, --output <json|raw>json for a machine-readable envelope; raw to unquote the --select result.
-s, --select <path>Dot/bracket path to extract, e.g. "records[0].sys_id". Implies machine-readable output.
 
# what is in my app's table right now?
npx @servicenow/sdk query x_786686_hr_leave_req_v2 -q "u_state=submitted" `
  -f u_number,u_state,u_days_count --display-value all --auth DEV

# grab a single sys_id for a script, unquoted
npx @servicenow/sdk query sys_user -q "user_name=admin" `
  -s "records[0].sys_id" -o raw --auth DEV

# did my business rule actually fire? check the audit table
npx @servicenow/sdk query x_786686_hr_leave_audit_v2 -q "ORDERBYDESCsys_created_on" `
  --limit 5 -f u_old_state,u_new_state,u_event_type --auth DEV

The --select plus --output raw pair is designed for shell command substitution, which makes this command genuinely scriptable rather than just a viewer.

4.3 The AI-assistant angle

This is the single most valuable thing in this document for anyone pairing the SDK with Cursor. Fluent's API surface is large and moves between versions, so a model answering from memory will confidently invent property names. explain --format raw emits clean markdown designed to be piped — which means you can ground the assistant in the exact API of your exact version:

# give the assistant the real API before asking it to write code
npx @servicenow/sdk explain scheduledscript-api --format raw | clip     # Windows
npx @servicenow/sdk explain scheduledscript-api --format raw | pbcopy   # macOS

Then paste it into the chat with "use this exact API". The repository's own Cursor rule already encodes this instinct — rule 2 in .cursor/rules/servicenow-sdk-master.mdc says to run explain when the API is uncertain. That rule is correct and worth keeping.

Validation for §4: npx @servicenow/sdk explain --list | Measure-Object -Line reports roughly 256 topic lines, and explain keys-file prints a document explaining why keys.ts must be committed — which is exactly what §5.3 covers next.

5.3 keys.ts — the most important file in the project

Every Fluent record can carry a $id, written as Now.ID['some_identifier']. The build maps each of those identifiers to a concrete ServiceNow sys_id and writes the mapping into src/fluent/generated/keys.ts as a TypeScript declaration:

// src/fluent/generated/keys.ts  — generated, ~1,340 lines in this project
import '@servicenow/sdk/global'

    namespace Now {

It says "generated", and you must still commit it. This trips up every team exactly once, and the damage is not obvious for weeks. Here is the failure chain, straight from the SDK's own ci-integration guide:

  1. You add a new business rule with $id: Now.ID['my_rule'] and build. A fresh sys_id is generated and written into keys.ts.
  2. You commit the business rule but not keys.ts, because "it's generated".
  3. A teammate builds. Now.ID['my_rule'] resolves to a different freshly-generated sys_id on their machine.
  4. ServiceNow identifies records by sys_id. So their install creates a duplicate record instead of updating yours. The target instance is now corrupted.
  5. Once a stale keys.ts reaches main, every later branch inherits the wrong IDs.

The guard is now-sdk build --frozenKeys in CI: it fails the build if keys.ts changed during it, which means someone forgot to commit. The developer's fix is trivial — run build locally, commit keys.ts, push. See §9.

9CI/CD done correctly

DevOps · from the SDK's own ci-integration topic

9.1 The two things CI must do

  1. Gate on --frozenKeys. Catch the uncommitted keys.ts before merge, not after it corrupts an instance.
  2. Authenticate without a keychain. CI has no OS keychain, so the CLI reads credentials from environment variables instead — but only when you explicitly switch it into CI mode.

9.2 CI mode and its environment variables

CI mode is gated by a single variable. Without it the CLI looks for a keychain and fails:

SN_SDK_NODE_ENVMust be exactly SN_SDK_CI_INSTALL. This is the switch.
SN_SDK_AUTH_TYPEoauth (recommended) or basic. Unset defaults to basic. Any other value is rejected before any network call.
SN_SDK_INSTANCE_URLFull instance URL.
SN_SDK_OAUTH_CLIENT_IDOAuth Application Registry client_id. Required when type is oauth.
SN_SDK_OAUTH_CLIENT_SECRETOAuth client_secret. Required when type is oauth.
SN_SDK_USER · SN_SDK_USER_PWDUsed only when type is basic.

Prefer OAuth. The client secret authenticates the CI system itself rather than impersonating a person, so a leak can be rotated without touching anyone's account, and there is no live user password sitting in a pipeline variable for a compromised job to exfiltrate.

9.3 Instance-side OAuth setup — all three steps are mandatory

  1. Service user. Must have the admin role, and must have Identity Type = Human on its sys_user record. The SDK's installer processor rejects non-human accounts.
  2. Enable the grant type. The system property glide.oauth.inbound.client.credential.grant_type.enabled must exist and be true. Create it in sys_properties if it is not there.
  3. Register the OAuth client in the Application Registry and map the service user from step 1 as the OAuth application user.
Set it up Application Registry (OAuth) System Properties Users

The CLI calls ${SN_SDK_INSTANCE_URL}/oauth_token.do once at startup with grant_type=client_credentials and uses the returned token for everything after. There is no refresh token in this grant; each run gets a fresh token.

    npx @servicenow/sdk install --auth $AuthAlias
    if ($LASTEXITCODE -ne 0) { Pop-Location; throw "Install failed: $app" }

    Pop-Location
}

Write-Host "`nAll 3 apps installed on '$AuthAlias'." -ForegroundColor Green

Three fixes versus the current script: the validate step is gone, $root now resolves to the workspace root instead of the scripts/ folder it was pointing at, and Pop-Location runs before each throw so a failure does not leave your shell in the wrong directory.

13.2 The six things that actually bite

Commit keys.ts

It says generated. Commit it anyway, or your teammate's install creates duplicate records. §5.3.

--reinstall deletes

It uninstalls first. Anything on the instance but not in your source is gone.

--async and --demoData default to true

Both surprise people. Set them explicitly in scripts.

There is no validate

And no upgrade, and no build --watch. §10.

One owner per artefact

SDK or Studio, never both for the same record. Install overwrites.

18-character scope limit

Including the prefix. Chosen at init and painful to change later.
