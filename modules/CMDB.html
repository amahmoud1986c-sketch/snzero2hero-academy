9) Best Practices & Common Mistakes

Open component:CIsCMDB WorkspaceCI Class ManagerApplication Services

Best practices:
- Follow CSDM — don’t invent your own structure.
- Let IRE manage identity; never bypass it on imports.
- Always coalesce on a stable unique attribute.
- Monitor CMDB Health continuously; assign data owners.
- Use the most specific CI class (not generic cmdb_ci).

Common mistakes:
- استيراد بلا coalesce → تكرار CIs.
- وضع كل شيء في cmdb_ci العام بدل الفئة الصحيحة.
- تجاهل CSDM فيصبح CMDB فوضويًا.
- تعطيل/تجاوز IRE.

function findBlastRadius(ciId, maxDepth) {
 var visited = {};
 var queue = [{id: ciId, depth: 0}];
 var result = [];
 while (queue.length) {
 var n = queue.shift();
 if (visited[n.id] || n.depth > (maxDepth || 4)) continue;
 visited[n.id] = true;
 if (n.depth > 0) result.push(n.id);
 var rel = new GlideRecord('cmdb_rel_ci');
 rel.addQuery('parent', n.id);
 rel.query();
 while (rel.next()) {
 queue.push({id: rel.child.toString(), depth: n.depth + 1});
 }
 }
 return result;
}

18.24 CMDB Health Score — target ≥ 80

Open component:CIsCMDB WorkspaceCI Class ManagerApplication Services

Formula (weighted average of 5 metrics, each 0–100):

Health = 0.30*Completeness + 0.25*Correctness + 0.20*Compliance + 0.15*Staleness_inv + 0.10*Duplicate_inv

Where:
- Completeness = % required attrs filled per class, averaged
- Correctness = IRE pass rate over last 30 days
- Compliance = % CIs with owner_by AND non-generic sys_class_name
- Staleness_inv = 100 - % stale (sys_updated_on < -90d)
- Duplicate_inv = 100 - (confirmed_duplicates / total_cis * 100)

Example numbers for HR Leave scope at Day 30:
- Completeness = 92
- Correctness = 96
- Compliance = 88
- Staleness_inv = 90
- Duplicate_inv = 99
- Health = 0.3092 + 0.2596 + 0.2088 + 0.1590 + 0.10*99 = 92.0 ✅ (≥ 80) — لو حاصلك أقل من 80، تابع: أولًا اكتمال البيانات، ثم تعيين المالكين، ثم تنظيف الـ stale.

Q1. In CMDB IRE, which option best describes an Independent Identifier?
A. An identifier that uses parent CI attributes
B. An identifier that uses one or more attributes of the CI itself
C. An identifier that requires Service Mapping
D. An identifier inherited from cmdb_ci_class_manager

Answer: B
Explanation: Independent identifiers use the CI’s own attributes (e.g., serial number for hardware). Dependent identifiers require a parent CI (e.g., disk depends on computer).

Q2. What is the correct CSDM domain order?
A. Build → Design → Foundation → Manage
B. Foundation → Design → Build → Manage
C. Design → Foundation → Manage → Build
D. Manage → Build → Design → Foundation

Answer: B
Explanation: Foundation (organizations, locations, contacts) → Design (services, applications, technical services) → Build (infrastructure CIs) → Manage (incidents, changes, etc. — operational data).

Q3. When two sources update the same CI’s os_version attribute with different values, which wins by default?
A. The most recently updated source
B. The source with the highest configured priority for os_version
C. The source that discovered the CI first
D. Both are kept; an issue is created

Answer: B
Explanation: Multisource CMDB uses per-attribute source priority. Last-wins is NOT the default.

Q4. Which Service Graph Connector pattern correctly enriches HR Profile CIs from Workday?
A. Custom REST script in cmdb_ci_person
B. Workday SGC + IRE rule on employee_number
C. Import Set with daily transform
D. SOAP integration with manual mapping

Answer: B
Explanation: SGC is the modern, governed path. IRE on employee_number ensures idempotency.

Q5. What does CMDB Health Completeness measure?
A. Number of CIs in production
B. % of required attributes populated for in-scope CIs
C. % of CIs without duplicates
D. % of CIs with correct class

Answer: B
Explanation: Completeness = required attributes filled. Correctness = no duplicates. Compliance = correct class.

Q6. A CI has been duplicated 5 times due to a discovery misconfiguration. Best remediation?
A. Manually delete all but the oldest
B. Run de-dup utility based on IRE identifier rules
C. Mark all 5 as retired
D. Update the discovery pattern, leave duplicates

Answer: B
Explanation: Use the de-dup utility based on IRE rules to merge duplicates. Manual deletion loses history.

Q7. Which is NOT a recommended approach for adding a custom CI class?
A. Use CI Class Manager
B. Extend from the closest base class
C. Add to Global scope to ensure visibility
D. Define IRE identifier for the new class

Answer: C
Explanation: Custom CI classes should be in a scoped app, not Global, to follow ServiceNow best practices.

Q8. What field on cmdb_ci_application_service distinguishes it from cmdb_ci_service?
A. service_classification
B. business_criticality
C. lifecycle_status
D. business_service_type

Answer: A
Explanation: service_classification = ‘application_service’ differentiates from business_service.

Q9. Why use Unified Map instead of legacy Dependency Views?
A. Faster rendering
B. Better mobile support
C. Supports multi-level relationships with filters
D. All of the above

Answer: D

Q10. Which APIs are recommended for programmatic CI creation respecting IRE?
A. Direct GlideRecord insert on cmdb_ci
B. IRE Command API (new IRECommand()…)
C. CMDB Service Graph API (/api/now/cmdb)
D. Both B and C

Answer: D
Explanation: Direct GlideRecord bypasses IRE; both IRE Command API and CMDB Service Graph API enforce identifier rules.
