0. Outcome and guardrails

Open component:Local Update SetsRetrieved Update SetsUpgrade HistoryDemandsProjectsPortfoliosResource Plans

Strategic Portfolio Management: Translate strategy into funded demands, portfolios, programs, projects, resources, costs, benefits, roadmaps, and measurable outcomes.

  • Confirm product entitlement before plugin activation.
  • Build and test in sub-production/PDI; never activate major plugins first in production.
  • Prefer out-of-box process/configuration before custom scripts.
  • Use Flow Designer for new automation; maintain legacy Workflow only when required.
  • Protect data with roles, ACLs, groups, criteria, and persona-based tests.
  • Australia is the deployment baseline; Brazil preview/EA is not the production baseline unless your organization explicitly validates it.

4. Roles, groups, and security model

Open component:ACLsRolesGroupsUsersLocal Update SetsRetrieved Update SetsUpgrade HistoryDemandsProjectsPortfoliosResource Plans

Typical roles: sn_ppm_read, it_project_manager, demand_manager, portfolio_manager, resource_manager, timecard_user, financial_admin

Professional rules:

  • Roles → Groups → Users; avoid direct role grants.
  • Separate admin/configurer, manager, fulfiller/agent, requester, auditor, and integration personas.
  • Test table, row, and field access with impersonation.
  • Never treat UI visibility as security; enforce ACL/criteria.
  • Record privileged access and quarterly access review.
