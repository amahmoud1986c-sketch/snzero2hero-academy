17.3 Discovery Admin Recipes

Open component:DiscoveryMID ServersAlertsApplication Services

Recipe A — Add new IP range + credential (5 minutes)

  1. Navigate: All > Discovery > Credentials → New. — Open direct
  2. Pick Type (Windows / SSH / SNMPv3 / vCenter / WMI).
  3. Fill user, password (or key), Applies to specific MID(s) if zone-scoped.
  4. Click Test Credential → pick a known target IP → must return Success.
  5. Navigate: All > Discovery > IP Networks → New. — Open direct
  6. Fill CIDR (e.g. 10.20.0.0/24), MID Server, Discovery Schedule (optional).
  7. Save → open a Discovery Schedule → add this network → Discover Now (small scope). — أضف بيانات اعتماد، اختبرها، أنشئ نطاق IP، اربطه بجدول، شغّل اكتشاف فوري على نطاق صغير.

Recipe B — Define new Pattern in Pattern Designer

  1. Navigate: All > Pattern Designer. — Open direct
  2. Click New Pattern → choose type (Infrastructure or Application).
  3. Set CI Type (e.g. cmdb_ci_apache_web_server).
  4. Add Identification Section (commands / WMI / SNMP / file parse) producing identification attributes.
  5. Add Connection Section to find related CIs (TCP/UDP listening ports → process).
  6. Use Debug mode → run on a test host via MID.
  7. Validate parsed values appear in Pattern Result preview.
  8. Save & publish → assign to Classification so future Discovery picks it up.
Common operations inside a pattern step:
- Parse Command Output (with delimiters / regex)
- Match (regex extract groups)
- Merge Table (combine into output variable)
- Set Parameter Value (assign to CI attribute)

أنشئ نمطًا، عيّن CI Type، أضف خطوات الهوية والاتصال، شغّل Debug، انشره ثم اربطه بالتصنيف.

Recipe C — Debug a failing probe via discovery_log

// Background script — last 24h failures grouped by sensor
var gr = new GlideAggregate('discovery_log');
gr.addQuery('sys_created_on', '>=', gs.beginningOfYesterday());
gr.addQuery('state', 'IN', 'error,warning');
gr.addAggregate('COUNT');
gr.groupBy('sensor');
gr.orderByAggregate('COUNT', 'sensor');
gr.query();
while (gr.next()) {
 gs.info('[discovery] sensor=' + gr.getValue('sensor') +
 ' failures=' + gr.getAggregate('COUNT'));
}

Steps:

  1. Run the script above in All > Scripts - Background. — Open direct
  2. Top offender → open discovery_log.list filtered by that sensor.
  3. Inspect Message field → most common errors:
    - Insufficient privileges → fix credential mapping.
    - Could not classify → missing/wrong pattern.
    - Connection refused → firewall or service down.
  4. Apply fix → re-run schedule on a single device. — شغّل السكربت لتجميع الفشل، افتح أعلى محسّس فاشل، اقرأ الرسالة، أصلح بيانات الاعتماد أو النمط أو جدار الحماية.
