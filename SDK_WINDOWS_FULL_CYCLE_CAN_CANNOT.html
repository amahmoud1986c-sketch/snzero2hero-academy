# Non-interactive (password from env — do not echo)
$env:SN_PASSWORD | npx @servicenow/sdk auth --add https://devXXXXXX.service-now.com `
  --type basic --alias DEV --username admin --password-stdin

# OAuth (interactive / registry client)
npx @servicenow/sdk auth --add https://devXXXXXX.service-now.com --type oauth --alias DEV_OAUTH

npx @servicenow/sdk auth --list
npx @servicenow/sdk auth --use DEV
npx @servicenow/sdk auth --print --format bearer --auth DEV
✓ Prefer alias + --auth DEV on every command ✓ OAuth for CI ✗ --oauth --client-id (flags do not exist) ✗ Commit .env with passwords

Verified against installed CLI 4.12.2 — full flag tables in SDK_CURSOR_FULL_DOCUMENTATION §3

# 1 auth     — credentials
npx @servicenow/sdk auth --list

# 2 init / create — scaffold or convert

  --scopeName x_786686_hr_leave --auth DEV
# convert legacy:  npx @servicenow/sdk init --from <sys_app_sys_id> --auth DEV

# 3 download — pull metadata for inspection (not Fluent)
npx @servicenow/sdk download .\download-out --auth DEV

# 4 build — compile Fluent → XML (this IS validation)
npx @servicenow/sdk build
npx @servicenow/sdk build --frozenKeys --errorOnConflict   # CI gate

# 5 install / deploy — push to instance
npx @servicenow/sdk install --auth DEV
npx @servicenow/sdk install --auth DEV --async false --demoData false
# DESTRUCTIVE:  npx @servicenow/sdk install -r --auth DEV

# 6 dependencies — types + app deps
npx @servicenow/sdk dependencies --auth DEV

# 7 transform — instance/XML → Fluent
npx @servicenow/sdk transform --table sys_script,sys_script_include --auth DEV
npx @servicenow/sdk transform --from .\exports\update_set.xml

# 8 clean — wipe dist/
npx @servicenow/sdk clean

# 9 pack — zip artefact
npx @servicenow/sdk pack

# 10 explain — 256 offline topics
npx @servicenow/sdk explain --list flow
npx @servicenow/sdk explain flow-api
npx @servicenow/sdk explain building-ai-agents-guide --format raw | clip

# 11 query — Glide-style from terminal
npx @servicenow/sdk query sys_app -q "scope=x_786686_hr_leave" -f name,scope,version --auth DEV
npx @servicenow/sdk query sn_vul_vulnerable_item -q "state=open" --limit 5 --auth DEV

# 12 cicd — App Repository publish / install / rollback
npx @servicenow/sdk cicd --help

Not commands: validate, upgrade, build --watch, auth --oauth (use --type oauth). See corrections in SDK flag doc §10.

7 · What the SDK CAN and CANNOT do

From Fluent FAQ + WFA + AI guides on SDK 4.12.2

7.1 CAN — first-class Fluent APIs

Application metadata as code: Tables, columns, choices, roles, ACLs, Business Rules, Client Scripts, Script Includes, UI Policies/Actions, Catalog items / Record Producers, Notifications, Properties, Application Menus/Modules, ATF tests, REST Message / Scripted REST (via dedicated APIs or Record()), Workflow Automation Flows (Flow(), triggers, actions, subflows), AI Agents / Agentic Workflows (SDK ≥ 4.4 — explain building-ai-agents-guide).

Lifecycle: init / init --from, transform (pull UI changes into Fluent), build, install/deploy, pack, cicd, query, explain, dependencies, hybrid apps (partial Fluent + XML).

Cross-scope / store apps: Depend on plugins, call typed APIs where published; wrap SecOps tables with your own scoped logic (Script Includes, Flows that use sn_vul_* records).

7.2 CANNOT — do these in the platform UI (or not at all via Fluent)

Design-time UI behaviour: Fluent does not run form UX, UI Policy preview, or Flow Designer’s live data-pill picker. Those stay in Studio / Flow Designer; sync with transform when needed. (SDK FAQ: no parity with dynamic editing surfaces.)

Redefine OOB plugin ownership: You cannot “Fluent-replace” ServiceNow’s Vulnerability Response plugin tables as if they were your scoped app. Do not ship competing dictionary on sn_vul_vulnerable_item from a custom scope expecting to own VR.

Scanner / spoke wizard UIs: Qualys/Tenable connector setup, Credential stores’ secrets UI, IntegrationHub spoke activation clicks — instance configuration, not Fluent source.

Some Process Automation / Playbook features: Public playbooks, certain experience-only activity types, legacy schema playbooks — configure in Workflow Studio; check explain playbook-* topics for current limits.

CLI myths: No validate, no upgrade, no build --watch. Validation = build. Upgrade SDK = change package.json + npm install.

Runtime data: Users, group membership, VI records, attachments, email history do not travel in Fluent install the way metadata does. Seed/migrate separately.

8.3 What SDK should do for VR/VRO

DO with SDK: Custom scoped app that orchestrates VR — Script Includes that query VIs, Flows that trigger on VI state change, notifications, integration Scripted REST into your app, ATF tests for your automation, AI agents that read VI summaries under invoking-user ACLs.

DON'T with SDK: Attempt to recreate the whole VR product in Fluent; overwrite OOB business rules on sn_vul_* without a clear upgrade plan; store scanner passwords in Fluent source.
